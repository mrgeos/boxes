# Box Studio 3D: заметки для работы над кодом

Редактор 3D-мокапов упаковки на Three.js. Пользователь пишет по-русски. Интерфейс и README тоже на русском. Заголовок файла (первая строка) пишется по-русски, комментарии в коде — по-английски.

## Главное
- Правьте `src/`, а не `box-studio-3d.html`. После правок выполните `npm run build` и закоммитьте собранный файл: перед пушем `npm run prepush` проверяет, что он совпадает со сборкой.
- Продукт идёт к веб-сервису (цель и направления — в начале `PLAN.md`). Жёсткого лимита на размер нет, но основной редактор держите лёгким (сейчас около 410 КБ, скрипт внутри сжат gzip): тяжёлое, что нужно не всем (импорт моделей, крупные библиотеки), загружайте по требованию, отдельным файлом. Учтите: файл больше ~1 МБ не откроется в предпросмотре приложения Claude, его придётся скачивать.
- CI в GitHub Actions нет. Все проверки запускаются только локально, перед каждым пушем в основную ветку (`claude/3d-box-mockup-designer-vq4cwt`): `npm run prepush` (ESLint, порядок модулей, собранный файл совпадает со сборкой, тесты в браузере; около 4 минут). Пока работаете в своей ветке, достаточно `npm run check` (секунды). В облачной сессии нужен `PW_CHROMIUM=/opt/pw-browsers/chromium`, `playwright install` не запускайте. Отдельный тест: `node test/run.mjs <часть названия>`.
- Тесты: редактор целиком клиентский, серверной части нет. Держите только короткие e2e для критичного (открытие, все заготовки, сохранение и открытие проекта, выгрузка файлов), юнит-тестов — минимум. Тесты на мелочи отдельных функций (разметка SVG, порядок слоёв, подписи) не добавляйте: они дорого поддерживаются. Новую функцию проверяйте глазами и снимками, а в тесты берите только то, что нельзя ломать никогда.
- Если переделка не должна менять поведение, сравните снимки до и после: `node test/snapshots.mjs <папка>` на старой и новой сборке, затем `--compare`. Файлы должны совпасть байт в байт: `Math.random` в тестах детерминирован.

## Устройство кода (подробнее — README, раздел «Разработка»)
- `src/app` — ES-модули, точка входа `main.js`. Импорты между модулями идут по кругу, поэтому на верхнем уровне модуля можно только объявлять. Обработчики событий и прочий код, который трогает другие модули, кладите в функцию `init…` и вызывайте её из `main.js`. Это проверяет `test/check-modules.mjs`.
- Импортированную переменную менять нельзя: модуль-владелец экспортирует для неё сеттер, например `setRecording`.
- Новая заготовка добавляется в `PRESETS` в `core/constants.js`. Новый носитель — файл в `carriers/` и ветки по `o.type` в `scene/renderer.js`, `core/model.js` (грани, размеры, развёртка) и `ui/model-panel.js`.
- Объекты и группы образуют дерево `state.tree` / `state.groups` (`core/groups.js`). Где стоит объект, решает `placeOf`: у объекта вне группы это его `pos`/`rotY`, у объекта в группе — раскладка ряда. После изменения дерева, настроек группы или поворота объекта вызовите `layoutAll()`. Новый объект без группы сам попадает в конец списка.
- 3D рисуется только при изменениях. Если сцена меняется не через `markFace`/`markObj`/`rebuildQueue` и не в ответ на ввод пользователя, вызовите `invalidate()` из `scene/camera.js`.
- `window.__boxStudio` нужен тестам. Не удаляйте из него то, чем пользуются `test/*.mjs`.

## Git
- Работайте в ветке, которую назначила сессия. PR направляйте в `claude/3d-box-mockup-designer-vq4cwt`. PR открывайте и мёржите только по просьбе пользователя. Перед пушем в основную ветку (в том числе мёржем PR) запустите `npm run prepush`.
